# ЭСТАФЕТА — передача проекта «Рубеж» в Claude Code на ПК

> Этот файл — первое, что читает Claude Code. Порядок: **ЭСТАФЕТА.md → docs/ТРЕБОВАНИЯ.md →
> DESIGN.md → CLAUDE.md**. Потом — код. Автор пишет по-русски, коротко и эмоционально; отвечать
> ему тоже по-русски, коротко, без жаргона. Он хочет **качество, красоту и отсутствие багов** и
> ждёт, что Claude сам предусмотрит проблемы (см. §7).

Дата передачи: 8 октября 2026. Подготовил Claude (облачная сессия «Графика и анимации»).
Код также лежит на GitHub: `Smetanik12/Project`, ветка **`claude/dreamy-dirac-sg8bpf`**.

## 1. Что это за проект

**Рубеж** — галактическая песочница на Godot 4.5: живой мир, который живёт без игрока
(RimWorld + Kenshi + EVE + Mount & Blade + экономика как в Victoria). Мир в 3D под углом,
персонажи — нарисованные 2D-спрайты (стиль HD-2D). Планеты огромные, жителей миллионы,
экономика честная (ничего из ниоткуда), ИИ умный, в любой дом можно зайти.

Полный замысел — `DESIGN.md`. Все пожелания автора дословно — `docs/ТРЕБОВАНИЯ.md`.

### История за один день
1. Чат «Привет»: выбрали Godot, диалоги без нейросети («действие × тема»), 4 сценария как в Kenshi.
2. Чат «Проверка доступности»: написан **2D-прототип** (карта 160×110 тайлов, ~100 NPC, слухи,
   фракции, торговля, диалоги, 4 сценария, сохранения). Работает, но графика простая.
3. Чат «Графика и анимации» (этот): автор потребовал красивую графику под углом, огромные планеты
   с миллионами жителей, честную экономику, большие города с районами и уникальными зданиями,
   дома с интерьерами. Поэтому начата **версия 2**: новый генератор планеты, чанки, планировки,
   интерьеры, 3D-отображение. 2D-прототип пока остаётся главной сценой, пока v2 не догонит его.

## 2. Как запустить на ПК (Windows)

### 2.0. Что установить (один раз)
| Что | Зачем | Где взять |
|---|---|---|
| **Godot 4.5 stable, Standard** (не .NET) | движок | https://godotengine.org/download/archive/4.5-stable/ → `Godot_v4.5-stable_win64.exe.zip`, распаковать в `C:\Godot\` |
| **Git for Windows** | история проекта; Git Bash — оболочка для Claude Code, хуков и `tools/check.sh` | https://git-scm.com/downloads/win |
| **Node.js LTS** | MCP-сервер Godot (`npx`) | https://nodejs.org/ |
| **Claude Code** | — | https://code.claude.com/docs/en/setup (PowerShell: `irm https://claude.ai/install.ps1 \| iex`) |

В `C:\Godot\` два файла: `Godot_v4.5-stable_win64.exe` (редактор) и
`Godot_v4.5-stable_win64_console.exe` (с консолью — **для тестов, скриншотов и Claude Code**).
Папку проекта держать по пути без пробелов и кириллицы, например `C:\Games\Rubezh`.

### 2.1. Первый запуск
Открыть проект в Godot (Import → `project.godot`), первый импорт ~1 мин. Рендер — **Forward+**
(нужна видеокарта с Vulkan, любая за последние ~8 лет). Если Godot ругается на Vulkan — обновить
драйвер видеокарты; временно можно запускать с `--rendering-driver d3d12`.

### 2.2. Проверки
У Claude Code на Windows две оболочки: **Git Bash** (инструмент Bash) и **PowerShell**.

Git Bash (и Linux/облако с `G=godot`):
```bash
G=/c/Godot/Godot_v4.5-stable_win64_console.exe
"$G" --headless --path . --import                                   # после новых class_name
tools/check.sh                                                      # синтаксис всех скриптов (Godot в C:\Godot найдёт сам)
"$G" --headless --path . --script res://tests/test_planet.gd        # «ВСЕ ПРОВЕРКИ ПЛАНЕТЫ ПРОЙДЕНЫ (2899)»
"$G" --headless --path . --script res://tests/test_sim.gd           # старый 2D-прототип: «ВСЕ ТЕСТЫ ПРОЙДЕНЫ»
"$G" --headless --path . --script res://tools/map_preview.gd -- --seed=7 --out=shots/map.png   # карта планеты
```
PowerShell:
```powershell
$G = "C:\Godot\Godot_v4.5-stable_win64_console.exe"
& $G --headless --path . --import
& $G --headless --path . --script res://tests/test_planet.gd
& $G --headless --path . --script res://tools/map_preview.gd -- --seed=7 --out=shots/map.png
```
Скрипт с `extends SceneTree` при ошибке **не завершается сам** — в Git Bash запускать через
`timeout 600 "$G" …` и смотреть, нет ли «SCRIPT ERROR». В облаке 3D-скриншоты — через
`xvfb-run -a -s "-screen 0 1600x900x24"` (пакет `mesa-vulkan-drivers`, см. `.claude/hooks/session-start.sh`).

### 2.3. Посмотреть новый 3D-мир
Открыть `scenes/explorer.tscn` в редакторе и нажать F6, или из консоли:
```bash
"$G" --path . res://scenes/explorer.tscn -- --site=rodnik --time=10 --dist=70 --pitch=48 --yaw=30
"$G" --path . res://scenes/explorer.tscn -- --site=arkon --time=19 --shot=shots/arkon.png   # снимок и выход
```
Снимки и карты ложатся в `shots/` (относительный путь — от папки проекта, папки создаются сами,
полный путь печатается в консоль; в git и в импорт Godot `shots/` не попадает). Claude Code
смотрит картинку инструментом Read.
Флаги: `--seed`, `--site=<id>` (`arkon`, `meridian`, `chernaya`, `svoboda`, `rodnik`, `zelen`,
`glotka`, `perekrestok`, `svalka`, `pepel_imp`, `pepel_front`, `village_123`…) или `--at=x,y` (тайлы),
`--time` (часы), `--winter=0..1`, `--dist`, `--pitch`, `--yaw`, `--shot=<png>`.
Управление: WASD — лететь, колесо — приближение, Q/E — поворот, R/F — наклон, T — +1 час.

Старый 2D-прототип: F5 (главная сцена `scenes/main.tscn`).

### 2.4. Claude Code на ПК: MCP-сервер Godot
Подключить один раз — в **Командной строке (cmd)**, открытой в папке проекта (в Проводнике
набрать в адресной строке `cmd` и нажать Enter):
```bat
claude mcp add godot -e GODOT_PATH=C:\Godot\Godot_v4.5-stable_win64_console.exe -- cmd /c npx -y @coding-solo/godot-mcp
```
Потом перезапустить Claude Code и проверить: `/mcp` (или `claude mcp list`) — `godot` подключён.
- `cmd /c` нужен на Windows: `npx` там — это `npx.cmd`, напрямую он не запускается.
- В репозитории есть `.mcp.json` с тем же сервером — для облака и Linux. Локальная настройка
  (команда выше) главнее проектной, поэтому на ПК работает она; `/mcp` может предупредить о двух
  определениях `godot` — это нормально.
- Claude Code может выполнить эту команду и сам, но сервер появится только после перезапуска.
Сервер умеет запускать проект, читать вывод и ошибки, создавать сцены. Картинки удобнее
снимать флагом `--shot` (§2.3).

### 2.5. Облачные сессии Claude Code
`.claude/settings.json` + `.claude/hooks/session-start.sh` сами ставят Godot 4.5, Vulkan на
процессоре (lavapipe), Xvfb и MCP-сервер. Работает после слияния ветки в `main`. На ПК хук
ничего не делает (сразу выходит).

### 2.6. Если что-то не так
- **Имена файлов после распаковки — кракозябры**: распаковать 7-Zip или WinRAR (или взять ZIP).
- **Git: «detected dubious ownership»** (папка на флешке или чужом диске):
  `git config --global --add safe.directory C:/Games/Rubezh`.
- **`$'\r': command not found`** в bash-скриптах — файл получил концы строк CRLF. В репозитории
  есть `.gitattributes` (всегда LF); починить файл: `dos2unix <файл>` в Git Bash.
- **Ошибка хука SessionStart на ПК** — нет Git for Windows (без него хуки идут через PowerShell).
  Поставить Git; хук на ПК всё равно ничего не делает, так что ошибка безвредна.
- **MCP `godot` не подключается**: `node -v` (нужен Node.js), проверить путь в `GODOT_PATH`,
  перезапустить Claude Code, `claude mcp list`.
- **Godot: «Your video card drivers seem not to support the required Vulkan version»** —
  обновить драйвер видеокарты; временно `--rendering-driver d3d12`.

## 3. Что сделано (и чем это проверено)

### 3.1. Генератор планеты — `scripts/sim/planet/` ✅
- `planet.gd` — **Planet**: непрерывный рельеф `height_base(x, y)` (материк-суперэллипс + шум,
  внутренние моря, хребты ridged-шумом с перевалами, холмы, мелкий рельеф), климат
  (`temperature`, `moisture`, `snow_line`), крупная сетка 512×256 (64 тайла на клетку: высота,
  температура, влажность, биом, хозяин, близость фронта, расстояния до моря и рек), реки и
  дороги с индексами по чанкам (`river_at`, `road_at`), поселения с индексом (`site_at`),
  кэш чанков (`chunk(cx, cy)`, потокобезопасный), запросы тайлов (`is_passable`, `height_at`…).
- `planet_gen.gd` — **PlanetGen.generate(seed)** за ~7,5 с: поля → сшивка суши перешейками →
  реки (истоки, спуск, слияния, ширина по стоку, монотонный уровень) → особые поселения
  (`data/landmarks.json`) → территории держав Дейкстрой по суше (Империя/Фронт, извилистая
  граница по горам и рекам) → выжженная зона фронта → пары окопов вдоль фронта → биомы →
  ~850 обычных поселений (поле расстояний, без пересечений) → дороги (A* по крупной сетке,
  остовное дерево + связи) → население по профессиям (`data/settlement_kinds.json`).
  Итог на сиде 7: **~867 поселений, ~3,2 млн жителей, 51 река, ~805 дорог, 14 окопов.**
- `chunk_gen.gd` — **ChunkGen**: чанк 32×32 тайла (64×64 м): высоты вершин с каймой (площадки
  поселений, полотно дорог, русла и берега, окопы, воронки), поверхность (16 типов), вода
  (уровни рек и моря), дороги и мосты, постройки (стены по граням тайлов, мебель), проходимость,
  деревья (15 видов, не стоят вплотную даже на стыках чанков) и мелочь (15 видов). ~20–40 мс.
- `layout_gen.gd` — **LayoutGen**: планировки. Малые поселения (деревня, хутор, рудник, форт,
  окоп, лагерь, логово, руины, пещера, обломки) — на сетке занятости, потом **проверка, что ко
  всем дверям можно дойти** (недоступное удаляется). Города — сетка проспектов/улиц, суперкварталы
  128×128, районы (дворец, высотки, жилые, промзона, пригород, трущобы, парки, площади, рынки,
  посадочные площадки), участки делением, на участке одно здание, общественные здания (19 видов),
  **мэрия** в центре, **цитадель столицы** со стенами, башнями и воротами на проспектах.
- `interior_gen.gd` — **InteriorGen**: первый этаж любого здания: комнаты по типу здания,
  внутренние стены и двери по граням тайлов, окна, лестница, мебель; **проверка связности** —
  мебель, отрезающая углы, убирается.
- `name_gen.gd` — названия по культурам (имперские латинизированные, повстанческие, вольные
  деревни из корней и суффиксов, пиратские, гильдейские) + формы «в/из/у».
- `site.gd`, `chunk.gd` — данные поселения и чанка.
- Данные: `data/landmarks.json`, `data/settlement_kinds.json`, `data/place_names.json`.

**Проверки** — `tests/test_planet.gd` (**2899 проверок, все проходят**): детерминизм (сид → та же
планета и те же чанки), население по профессиям = общее, поселения не пересекаются, особые места
на месте, окопы на своих территориях; для образцов всех видов поселений: **постройки не
пересекаются, не стоят на воде и дорогах, двери не заблокированы, от центра можно дойти до
каждой двери, внутри зданий нет отрезанных клеток, деревья не на постройках/дорогах/воде**;
случайные чанки без мусора в высотах; скорость.

## 4. Что НЕ сделано и известные проблемы

1. **Здания в 3D не рисуются.** Сейчас на месте домов видны серые квадраты пола (тип PAVED). Это
   следующий шаг (§5, шаг 2).
2. **Свет в 3D пересвечен**, картинка блёклая (экспозиция, туман, окружение подобраны «на глаз»
   под программный Vulkan). Настроить на настоящей видеокарте: `sky_controller.gd` —
   `tonemap_exposure`, `ambient_light_energy`, `fog_*`, `adjustment_*`.
3. **Нет дальнего LOD рельефа**: за радиусом 7 чанков (~450 м) пусто, прикрыто туманом.
   Камера ограничена 140 м. Для вида на горизонт нужен грубый слой (суперчанки 4×4 с шагом 4 тайла).
4. **Симуляция v2 не начата**: в новом мире нет людей, экономики, времени. Старая симуляция
   работает только с 2D-картой.
5. **Персонажей в 3D нет** (план — §5, шаг 4).
6. Генерация планировки большой деревни при первом приближении — 0,3–1 с (идёт в потоке, рывков
   нет, но можно ускорить).
7. Папка `BotTG/` — старый телеграм-бот, автор разрешил удалить.
8. Один генерируемый мир (Рубеж, развитый). Нет профилей планет (неразвитая — без городов) и
   галактики.
9. Перешейки иногда получаются широкими; «внутренние моря» иногда очень большие — поправить
   параметры `continent()` после осмотра карты (`tools/map_preview.gd`).
10. Дороги внутри городов: внешняя дорога доходит до центра города, участки её обходят — получается
    «диагональный бульвар». Можно обрезать дороги на краю города (`_make_road`) и стыковать с проспектом.
11. Квоты не всегда набираются: пещер выходит ~6 из 40 (условие «подножие гор и высота > 25 м»
    слишком строгое), городков ~34 из 46 (зазор 24 клетки). Ослабить условия в `PlanetGen._score`
    и `QUOTA`, проверить `tools/map_preview.gd`.
12. В городах улицы и тротуары одного материала (PAVED) — без зданий столица выглядит сплошной
    мостовой (см. `docs/screens/12_…`). В шейдере рельефа использовать флаг дороги (атлас, канал G,
    бит 1) для асфальта/брусчатки и бордюров; тротуары — светлая плитка.
13. Дымка и туман слишком сильные, цвета блёклые (см. §4 п.2).
14. Окопы `pepel_imp` и `pepel_front` стоят в ~6 клетках (≈380 м) друг от друга — это и есть
    «ничья земля». Старая игровая логика штурмов рассчитана на 2D-карту; в v2 её надо переписать.

## 5. План работ — по шагам

Правило: **один шаг — одна сессия**. В конце шага: тесты зелёные, скриншоты посмотрены глазами,
`DESIGN.md` отмечен, коммит. Перед каждым шагом — перечитать требования автора по теме.

### Шаг 1. Довести 3D-основу до красоты (1 сессия)
- Подстроить свет и цвет (§4.2): день, рассвет, закат, ночь, зима. Скриншоты всех биомов:
  луга, лес, тайга, тундра/снег, пустыня, бесплодные земли (красный камень), джунгли, болото,
  горы, пепельный фронт с воронками, побережье, река с берегами.
  Поиск мест: `tools/map_preview.gd` → координаты → `explorer --at=x,y`.
- Проверить воду (пена, прозрачность), деревья (масштаб 12–25 м, ветер), траву вблизи.
- Дальний LOD (§4.3) и туман.
- **Профиль планеты** (требование автора): `PlanetGen.generate(seed, profile)` с полями
  `tech` (0 — племена … 4 — ядро империи), `owner`, `contested`, `biome_bias`. При `tech <= 1` нет
  городов, только деревни, хутора и лагеря; при 2 — городки; 3 — города; 4 — мегаполисы.
  Тест: на неразвитой планете ноль городов.

### Шаг 2. Здания в 3D (1–2 сессии) — самое заметное
Файлы: `scripts/view/building_mesher.gd`, `shaders/building.gdshader`, подключение в `PlanetView`.
- Постройки чанка берутся из `chunk.own` (пары [Site, словарь]); план этажа —
  `InteriorGen.ground_floor(st, s)`.
- **Стены — по граням тайлов** (`walls`, `doors`, `windows` из плана): сегмент стены 2 м длиной,
  толщина 0,25 м, высота этажа `LayoutGen.FLOOR_M = 3.2`. В проёмах дверей — коробка двери,
  в окнах — проём с рамой и стеклом (стекло светится ночью, случайно по хэшу окна).
- Пол, перекрытия, лестница, крыша по `roof`: `gable`, `hip`, `flat` (с парапетом, кондиционерами,
  антеннами), `dome`, `thatch`, `shed`, `tent`, `none`. Верхние этажи пока «коробкой» с окнами.
- Материалы по `style` (культура) и уровню техники: имперский камень/бетон с красными знамёнами;
  повстанческий кирпич; гильдейское стекло и сталь с жёлтым; синдикат — тёмный металл с фиолетовым
  неоном; вольные — дерево, штукатурка, солома; мусорщики — ржавый лом.
- **Уникальный облик** общественных зданий (мэрия с колоннами и флагом, больница с крестом и
  площадкой, полиция с синей полосой, храм с куполом, электростанция с трубами, ПВО с пусковыми,
  узел связи с мачтой, тюрьма со стенами и вышками, космопорт с кораблём).
- Мебель — простые модели по видам из `InteriorGen.FURNITURE`.
- **Вырез** (cutaway): когда игрок внутри здания — прятать крышу и этажи выше игрока.
- Окопы (`trench` — понижение уже в рельефе; бруствер из мешков по `parapet`), колючка (`wire`),
  стены и башни цитадели и фортов (`posts` — площадки наверху), причалы с лодками, поля с рядами
  растений по `crop`, выпасы с изгородью и животными, площади, рынки с навесами, парки.
- Склеивать меши чанка по материалам (мало вызовов отрисовки), крыши — отдельно по зданиям
  (для выреза).
- Тест: здания не висят и не тонут (низ = высота площадки), ночные окна светятся.

### Шаг 3. Симуляция v2 (2–3 сессии) — сердце игры
Подробный замысел — `DESIGN.md` §4–5. Новые файлы в `scripts/sim2/` (старые не трогать, пока
не перенесено всё нужное):
- **Время**: тик = 4 игровые секунды, x1 = 20 тиков/с (день ≈ 18 мин), x2, x3, x4 для путешествий;
  обновления с переменным шагом `advance(dt)`, почасовые/суточные события при пересечении границ.
- **World2**: планета (сид) + изменчивое состояние: поселения (`Site.pops/stock/money/faction`),
  ресурсы природы (запасы рыбы в реках и озёрах, лес, руда, плодородие полей), фракции, факты,
  движущиеся группы (караваны, армии), постоянные NPC (с кем говорил игрок, ключевые), игрок.
- **Экономика без «из ниоткуда»**: рецепты профессий в `data/professions.json` (рыбак: рыба из
  запаса водоёма; фермер: зерно с полей по сезону; лесоруб: лес; шахтёр: руда; плавильщик:
  руда+топливо→металл; кузнец: металл→инструменты/оружие; портной; повар; травник/медик; рабочие
  фабрик в городах). Потребление: еда, вода, одежда, топливо (зимой больше), лекарства. Цены от
  запаса и спроса. Торговля — потоки по дорогам с задержкой + видимые караваны рядом с игроком.
  **Тест сохранения товаров**: Δсклада = добыто − съедено ± привезено/увезено, ни одного
  отрицательного склада, рыбы в деревне ровно столько, сколько поймали.
- **Материализация** (пузырь ~250 м вокруг игрока): люди появляются из населения поселения в
  конкретных домах (`cap` здания), личность детерминирована: `hash(site, дом, номер)` → имя,
  черты, профессия, внешность. Ушёл и вернулся — тот же человек. Говорил с игроком → становится
  постоянным. Работа материализованных — «вживую» (рыбак идёт на причал `spot`, ловит, несёт улов
  в амбар `work=store`), остальные — сводно, без двойного счёта.
- **Навигация**: граф AStar3D по загруженным чанкам (тайлы + этажи), рёбра режутся стенами по
  граням (`chunk.walls`), двери открывают проход; лестницы связывают этажи; добавление/удаление
  узлов при загрузке/выгрузке чанков. Дальние NPC и группы движутся по полилиниям дорог абстрактно.
- **Распорядок дня** NPC: дом → работа → рынок/таверна → сон; охрана на `posts` (крыши, башни,
  стены — их видно, камера под углом).
- **Факты и слухи** — перенести из 2D (`fact.gd`, `fact_text.gd`, `rumors.gd`) с «пулами знаний»
  поселений; фракции узнают новости, когда те доходят до их поселений.
- **Фракции и война** (требование автора): война за поселения как пункты снабжения; на обычных
  планетах — орбитальные удары по ПВО, связи, штабам, складам, космопортам (эти здания уже есть в
  планировках: `aa_battery`, `comm_center`, `hq`, `depot`, `landing_pad`) → десант во все города;
  окопный фронт — только при равенстве сил (Рубеж).
- **Уровень развития планеты = сумма её поселений**: связь есть, пока цел узел связи; торговля с
  галактикой — пока цел космопорт; сложные товары — пока целы фабрики. Разрушили город — планета
  теряет связь и преимущества.
- Перенести **диалоги** (`scripts/sim/dialogue.gd`) и **сценарии** (раб на руднике «Глотка»,
  офицер в Цитадели Аркон, крушение у линии фронта, солдат в окопе «Пепельный хребет»).
- Сохранение: сид + изменчивое состояние (поселения, ресурсы, факты, постоянные NPC, игрок,
  повреждения зданий).
- Тесты: 30 дней сводной симуляции без голода-лавины; 3 дня с пузырём; NPC не стоят в стенах;
  сохранение/загрузка; скорость (≤ 5 мс/тик при 250 материализованных).

### Шаг 4. Персонажи 2D в 3D (1–2 сессии)

## 6. Правила работы и подводные камни (выучено на практике)

- После **каждого** изменения: `tools/check.sh` (или цикл `--check-only` по скриптам), нужные
  тесты, для графики — скриншот и **посмотреть его**. Не говорить «готово», не проверив.
- Новый `class_name` → сначала `godot --headless --path . --import`, иначе «Identifier not declared».
- **Нельзя называть методы** `_get`, `_set`, `_init` с другими параметрами, `_notification` и т.п. —
  конфликт с виртуальными методами Object (ловили дважды).
- `var x := arr[i]` / `:= dict[k]` / `:= [a, b][i]` — «Cannot infer the type»: писать тип явно.
- `PackedFloat32Array` не имеет `max()`; `Vector2 <= Vector2` сравнивает лексикографически.
- Скрипт с `extends SceneTree` при ошибке **не выходит сам** — запускать с `timeout`, следить за
  «SCRIPT ERROR» в выводе.
- Потоки: `planet.chunk()` можно звать из рабочих потоков. Словари построек **не менять** после
  генерации (их читают разные потоки); кэши — в `Site` под `st.mutex` (`blocks`, `plans`).
  Каждую задачу `WorkerThreadPool.add_task` обязательно дождаться (`wait_for_task_completion`).
- Детерминизм: всё из сида через `U.hash3/U.rnd3` или свой `RandomNumberGenerator` с сидом от
  координат/id. Никаких `randi()` в генерации.
- Производительность GDScript: вызов шума ~0,25 мкс, итерация цикла ~0,03 мкс — считать бюджеты.
  Тяжёлое — в потоки; в главном потоке ≤ 5 мс на подгрузку за кадр.
- Буфер MultiMesh: 12 чисел на экземпляр — строки 3×4: `(bx.x, by.x, bz.x, o.x, bx.y, by.y, bz.y, o.y, bx.z, by.z, bz.z, o.z)`.
- Порядок в Godot: «лицевая сторона» треугольника — по часовой стрелке при взгляде на неё.
  Для растительности материал двусторонний (`cull_disabled`), нормаль переворачивается в шейдере.
- Глубина в шейдерах воды (Forward+, обратный Z): `vec3 ndc = vec3(SCREEN_UV * 2.0 - 1.0, depth)`.
- Не пушить в `main` без просьбы автора; работать в своей ветке, коммиты на русском.

## 8. Журнал решений (почему так)

| Решение | Почему |
|---|---|
| Godot 4.5, Forward+ | бесплатный, лёгкий для ИИ, хороший 3D; Forward+ — тени, SSAO, glow, сотни ламп ночью |
| HD-2D: мир 3D, люди 2D | автор просил вид под углом и людей на крышах/башнях; 2D-спрайты позволяют рисовать одежду слоями и делать много вариантов внешности процедурно |
| Всё процедурное, без покупных моделей | единый стиль, нет лицензий, подстраивается под любые размеры зданий; CC0-наборы Quaternius/Kenney можно добавить позже для мелочей |
| 1 тайл = 2 м, планета 32768×16384 | 65×33 км — «реально большая»; точность float32 на этих расстояниях ≤ 4 мм, плавающий начальный отсчёт не нужен |
| Лениво по чанкам | вся планета не помещается в память и не считается за разумное время |
| Один материк + перешейки | раньше планета распадалась на острова, войне и торговле некуда было идти |
| Территории только у держав | обычная планета принадлежит одной державе; организации владеют поселениями |
| Стены по граням тайлов | в дома можно заходить и рушить их по сегментам; комнаты не съедаются толстыми стенами |
| Сетка занятости + проверка доступности | гарантия «объекты не заходят друг в друга», «у каждой двери есть проход» |
| Две детализации деревьев через visibility_range | без кода переключения, плавно |
| Атлас поверхности 512×512 по модулю | шейдер видит соседние чанки — нет швов смешивания |
| Уровни детализации симуляции | миллионы людей нельзя считать по одному; одни правила на двух уровнях = честная экономика |
